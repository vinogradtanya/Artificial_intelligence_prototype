## 2. Назначение и цели создания системы

**Назначение.** Демонстрация ключевых механик сервиса генерации контента на основе
пользовательских промптов: регистрация, работа с проектами, имитация генерации,
учёт токенов, модерация, роли и отчётность.

**Цели создания:**

1. Показать полный пользовательский сценарий «регистрация → генерация → библиотека → отчёты».
2. Реализовать разграничение прав (пользователь / администратор).
3. Реализовать учёт расхода токенов и его пополнение (имитация оплаты).
4. Отработать процессы ЖЦ и испытания согласно ГОСТ Р 57193-2025 и ГОСТ Р 59792-2021.

**Критерии достижения целей (для прототипа):**

- все обязательные функции доступны и покрыты автотестами;
- система запускается одной командой и не требует внешних платных сервисов;
- объём данных — 10–20 пользователей в тестах (см. п. 10).

## 3. Характеристика объекта автоматизации

Объект — деятельность пользователя по созданию контента с помощью ИИ. В прототипе
«ИИ» заменён Mock-генератором, выдающим заранее подготовленные/детерминированные
результаты. Система многопользовательская, развёртывается локально (один узел).

## 4. Требования к системе

### 4.1. Требования к системе в целом

- Архитектура: клиент-серверное веб-приложение (серверный рендеринг, HTTP).
- Режим работы: круглосуточный для сервера; для прототипа — локальный запуск.
- Разграничение доступа: ролевая модель (`user`, `admin`).
- Хранение данных: реляционная БД (SQLite в прототипе; PostgreSQL/MySQL — перспектива).
- Пароли хранятся **только** в виде хеша (`pbkdf2:sha256`).

### 4.2. Требования к функциям (обязательные)

| Код | Функция | Результат |
|---|---|---|
| Ф-01 | Регистрация пользователя | Создание учётной записи; стартовый баланс 100 токенов |
| Ф-02 | Авторизация (логин или email + пароль) | Сессия пользователя |
| Ф-03 | Выход из системы | Завершение сессии |
| Ф-04 | Профиль пользователя | Просмотр/изменение email и пароля |
| Ф-05 | Выбор тарифа | free / pro / business, влияет на стоимость |
| Ф-06 | Создание проекта генерации | Форма: тип контента, промпт, параметры |
| Ф-07 | Имитация генерации | Текст (шаблоны), изображение (PNG), аудио (WAV) |
| Ф-08 | Модерация промпта | Отклонение при наличии запрещённых слов |
| Ф-09 | Списание токенов | Списание стоимости при успешной генерации |
| Ф-10 | Пополнение баланса (имитация оплаты) | Увеличение баланса + транзакция |
| Ф-11 | Библиотека результатов | Список и просмотр результатов пользователя |
| Ф-12 | История генераций | Фильтры по дате и типу контента |
| Ф-13 | История транзакций | Фильтры по дате |
| Ф-14 | Экспорт отчётов | CSV или JSON |

### 4.3. Требования к видам обеспечения

- **Информационное:** БД из таблиц `users`, `generations`, `transactions`, `audit_log`
  (см. `schema.sql`).
- **Математическое:** расчёт стоимости генерации: `стоимость = базовая × коэффициент тарифа`;
  бонус пополнения — процент от суммы; Mock-генерация — детерминированная функция
  от SHA-256 хеша промпта.
- **Программное:** Python 3.11+, Flask 3, Pillow, стандартные модули `sqlite3`, `wave`,
  `struct`, `hashlib`, `subprocess`, `urllib`. Реальная генерация изображений —
  сервис Pollinations.AI; реальная озвучка — Windows SAPI5 (`System.Speech`).
  Тесты — pytest.
- **Техническое:** ПК/ноутбук; 1 ядро CPU, ≥2 ГБ ОЗУ, ≥500 МБ диска; ОС Windows/Linux/macOS.
- **Лингвистическое:** интерфейс на русском языке; UTF-8.
- **Организационное:** эксплуатация одним пользователем на одном узле (прототип).
- **Методическое:** руководство пользователя (`docs/Руководство_пользователя.md`).

## 5. Состав и содержание работ по созданию системы

Работы выполняются итерационно; подробно — в `docs/Стадии_разработки.md`.

4. Эскизный проект (структура БД, схема экранов).
5. Технический проект (модули Python, шаблоны, схема БД).
6. Разработка рабочей документации и кода.
7. Ввод в действие (локальный запуск, демонстрация).
8. Сопровождение (учебное: исправление замечаний, доработка).

## 6. Порядок контроля и приёмки

См. `docs/Программа_и_методика_испытаний.md`. Кратко:

## 7. Требования к подготовке объекта автоматизации

Подготовка сводится к локальной установке зависимостей и созданию БД:

1. Установить Python 3.11+ и зависимости (`pip install -r requirements.txt`).
2. Инициализировать БД и, при необходимости, наполнить демо-данными (`python seed.py`).
3. Обеспечить права на запись в каталог `storage/` (БД и медиафайлы).

## 10. Обязательные и перспективные требования

### 10.1. Обязательные требования (реализовано)

Полностью совпадают с перечнем функций Ф-01…Ф-18 (раздел 4.2). Реализованы в коде и
покрыты автотестами (`tests/`, 82 теста, все проходят).

### 10.2. Перспективные требования (вне объёма учебного проекта)

| Код | Требование | Причина исключения | Заглушка в прототипе |
|---|---|---|---|
| П-01 | Интеграция с реальным AI-API (текст) | Платно / лимиты; нестабильность | Mock-генератор; опц. HF API |
| П-02 | Реальная оплата (эквайринг) | Вне учебной задачи | Кнопка «Пополнить» → запись в БД |
| П-03 | Модерация ML-моделью | Нужна обученная модель | Проверка по списку слов |
| П-04 | Экспорт PDF/Excel | Отдельная задача | CSV / JSON |
| П-05 | Масштаб на 1000 пользователей | Учебный объём | 10–20 пользователей в тестах |
| П-06 | Резервное копирование | Инфраструктурная задача | Только декларируется |
| П-07 | PostgreSQL/MySQL в проде | Достаточно SQLite | SQLite; драйверы доступны |
| П-08 | Тёмная/светлая тема (переключатель) | Опционально | Реализована тёмная тема |
| П-09 | Полноценный RAG-ассистент (векторная БД, история диалога, модерация ответов) | Отдельный объём работ | Справочник по базе знаний + LLM по ключу (Ф-17, Ф-18) |

### 10.3. Допущения и ограничения

- Система не предназначена для промышленной эксплуатации.
- Результаты генерации — демонстрационные (детерминированные), а не «настоящий» ИИ.
- Секретный ключ и учётные данные по умолчанию **подлежат замене** перед любым
  реальным использованием.
- Конкурентный доступ многих пользователей не тестировался (один узел, SQLite).
